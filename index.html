▶ 01. Dual Static & Dynamic Quadtree Spatial Partitioning 0.577 ms → 0.021 ms

Architecture: Designed and implemented a dual-tree spatial partitioning system to handle fast circular area queries (getObjectsInCircularArea) during multi-enemy combat without linear O(N) scene scans.

  • Static Quadtree: Built once at scene load time to index immutable level geometry and static environment props.
  • Dynamic Quadtree: Lightweight spatial tree rebuilt every frame exclusively for active gameplay tags (PLAYER, ENEMY, PROJECTILE, BREAKABLE), keeping query candidate counts minimal.

▶ 02. In-Editor Play Mode & Deep Cloning Pipeline Engine Tools

Goal: Designed and built the editor's runtime simulation pipeline (Play / Pause / Stop) so designers could test gameplay directly inside RavEngine and restore the original scene on Stop without slow disk serialization.

  • In-Memory Scene Snapshot: Deep-clones the active Scene hierarchy and all attached components when entering Play Mode, keeping the editor scene untouched.
  • Pointer Remapping Pass: Maps original pointers to cloned instances via an std::unordered_map and runs fixReferences() so cross-component references point to the new runtime objects with zero disk I/O.
// Post-cloning pointer remapping pass (zero disk I/O)
void Scene::fixClonedReferences(
    const std::unordered_map<GameObject*, GameObject*>& instanceMap) 
{
    for (auto& [originalObj, clonedObj] : instanceMap) {
        for (Component* comp : clonedObj->getComponents()) {
            comp->fixReferences(instanceMap);
        }
    }
}

Architecture: Built a modular, decoupled character control architecture to support two distinct playable characters (Lýriel and Death) without tangling input handling, locomotion, and combat logic:

▶ 04. UID-Based Checkpoint & World State Persistence Gameplay Systems

Goal: Players needed mid-level checkpoints so dying wouldn't force them to replay the entire level. Instead of relying on full scene serialization to disk (which would introduce unnecessary I/O overhead during gameplay) I created a lightweight in-memory persistence manager:

  • In-Memory State Manager: Created PersistingCheckpointState (Singleton) to persist world flags across full scene reloads without storing raw GameObject* pointers (avoiding dangling references).
  • UID-Based State Flags: Defeated enemies, broken props, and triggered events register their persistent UID as boolean state flags; on respawn, entities query their UID during Start() to restore the level state.
  • Double-Buffered Progress: Separates temporary progress (m_deadEnemies) from confirmed progress (m_deadEnemiesPersistent), committing state flags only when crossing a checkpoint.
  • Trigger & Editor Lifecycle: Differentiates one-shot narrative triggers from resettable music events, and purges all cached state via OnGameStop() when exiting Play Mode.

▶ 05. Gameplay Mechanics: NavMesh-Constrained Dash & Breakables Gameplay Features
  • NavMesh-Constrained Dash: Implemented the dash movement using NavMesh spatial queries so the player couldn't clip through walls or dash out of bounds.
  • Reusing Area Modifiers: Leveraged existing NavMeshModifier area flags (originally built to restrict paths exclusive to the second playable character) to filter valid dash destinations cleanly without duplicating collision logic.
  • Interactive Breakables: Built specific breakable environment variants (crates, barriers, and combat-reactive props) on top of our base destructible component.
  • System Integration: Hooked breakable destruction events into pickup/drop spawning, VFX triggers, and checkpoint UID persistence.
